# 01 — Translation Inventory (User-Facing Text)

Audit-only artifact for OptiFleet bilingual (English / Indonesian) preparation. Source of truth: `main` @ 3e55571 (the audit branch has no content difference from `main`). No source code, i18n framework, locale file, enum, workflow, permission or database change was made.

## How this inventory was produced

- **Frontend** (`frontend/src`, 268 `.ts/.tsx` files): parsed with the TypeScript compiler AST (not grep). Every JSX text node, every string/template literal in a JSX attribute, object property, function argument, default parameter, array, return value or conditional branch was extracted with its parent JSX element chain, enclosing component, attribute/property name and the variable it belongs to. Mixed JSX children (`Delete {name}?`) were merged into one parameterized template. Config-driven labels were traced to their definitions: `layouts/tenantNav.ts` (menu), `navigation/breadcrumbLabels.ts`, column configs (`header`), tab arrays, status/enum label maps, option helpers (`inspectionOptions.ts`, `masterTypes.ts`, `workspaceAssignment.ts`), component defaults (`States.tsx`, `ConfirmDialog.tsx`, `StatusBadge.tsx`).
- **Backend** (`backend/app`, `routes`, `bootstrap`, `config`, production seeders, `resources/views`; 791 files): parsed with PHP `token_get_all`. Each literal (including interpolated strings and heredoc/nowdoc templates) was tied to its enclosing call (`new XException(`, `abort_unless(`, `ValidationException::withMessages`, `->json`, `$fail`), array key (`label`, `display_name`, `action_label`, validation `field.rule`), constant and class. HTML print templates were split into static text nodes; `{{variables}}` are kept as parameters. Workflow status / action labels that the seeder *generates* from codes (`ucwords`) were reconstructed from the seeder definitions.
- **Excluded by rule** (not inventoried): CSS/class names, routes/URLs, permission keys, DB columns, canonical enum values used as identifiers/comparisons, MIME types, SQL, XML, log lines, artisan CLI output (157 strings, operator-facing), demo/functional-test seeders (448 strings: demo company/vehicle/user-generated text), tests. Dynamic values (transaction numbers, VIN, plates, SKU, serials, amounts, names) appear only as `{{parameters}}`.
- **Consolidation**: occurrences with the same text and the same meaning group (e.g. a field name used as a form label and as a column header → one `fields` key) are merged; the same text with a different meaning (e.g. `Cancel` the button vs. `Cancel` as an option/label) keeps separate entries. A frontend string used by 3+ modules or defined in a shared component becomes `common.*` (GLOBAL).

## Where the full inventory lives

The complete row-level inventory (5128 rows) is `docs/i18n/translation-inventory.csv` with the columns: `no, source_text, category, scope, module, translation_key, source_file, context, occurrence_count, dynamic, need_translation, notes`. `source_file` is the first occurrence (`path:line`) plus the number of other files; `context` starts with the component/function. This markdown file lists the **GLOBAL** and **DOMAIN** scopes in full (the shared vocabulary every module depends on); MODULE, DOCUMENT and BACKEND rows are in the CSV and summarized per module in `05-i18n-audit-coverage.md`.
